# 统一病变所见模型：设计稿（2026-11-10）

状态：**草稿，待研究者批准**。批准前不修改 `Proposal_v5.md`，不写产品代码。
来源：2026-11-10 与研究者的对话。标注"研究者定"的是研究者的原话；标注"执行方定"的是执行方补全的选择，研究者可以改。

## 1. 意图

给模型一份 MRI 影像和它的扫描协议，模型找出病变，圈出大致位置，并说明"在某某解剖结构上，疑似某某异常"。成果给医生看。对错的标准是医生在数据集里留下的标注：医生怎么标，模型就给出同样形式的结果，并与之一致。（研究者定）

原方案（`Proposal_v5.md` v5.1）要求逐体素描出病变边界，并要求同一个模型兼顾单层和三维。前者需要专家逐体素标注，目前没有来源；后者是剩余工作里最大的一块。研究者决定两者都不再作为目标。

## 2. 目标

1. **一个模型处理两种协议。** 膝关节 qDESS 双回波（SKM-TEA）和脑 DWI + ADC（ISLES-2022）由同一个 checkpoint 处理。（研究者定）
2. **输出形式跟随医生的标注。**（研究者定）
   - 膝：六块组织的轮廓；病变框，每个框带病变类别和所在组织组。
   - 脑：梗死轮廓，说明"疑似缺血性梗死"；不报解剖结构，因为数据里没有脑部组织标注。
3. **只做三维。** 研究者定"三维或二维一种即可"；选三维是执行方定，因为现有基线和代码都是三维的。
4. **成功标准沿用基线指标。**（研究者定）
   - 膝组织轮廓：每类 Dice，对照基线 0.831–0.887。
   - 脑梗死轮廓：Dice、病灶检出率、每例误报数，对照基线 0.752 / 0.641 / 2.342。
   - 统一模型的这些数值与单独训练的基线相比"不应明显变差"。没有设数值界限；报告并列给出差值，由研究者判断。（执行方定）
5. **膝病变框的评价**沿用研究者 2026-11-07 采纳的 S7：预测病变的定位点落在医生的框内算命中；所在组织组也一致才算归属正确；分母固定为医生的全部主分析框。（执行方定，见 §5 的一处偏离）

## 3. 非目标

- 体素级的病变边界验证（膝）。
- 二维单层模式，以及二维、三维共八项能力验收。
- SPIDER 和其他未批准的数据。
- H1、H2、H3 三个假设不再是独立目标。它们原本是为最终目标服务的手段。（研究者定）
- 消融实验（研究者 2026-11-10 搁置）。
- 读取 DICOM 文件的入口。它是最终目标的一部分，但需要真实的 DICOM 样本才能验证，另立计划（§8）。

## 4. 反目标（做到了也算失败）

- 把"医生没标"说成"正常"。膝关节数据没有确认阴性：模型没圈出病变时，输出只能说"未见所列异常"，并注明未标注不等于正常。
- 把框外的预测记成误报。医生没标的地方不等于没有病变，这类预测只作描述性计数。
- 把统一模型的结果写成体素级能力或 `core_target_validated`。
- 训练或选模型时读到正式划分之外的数据。官方 test 的框已在导入结果里，必须按冻结划分的角色读取。

## 5. 做法

### 5.1 模型

共享一个编码器；每个协议有自己的输入层、解码器和输出头。扫描协议决定走哪一组输入层和输出头，这就是"协议作为输入"的含义。（执行方定）

- 沿用现有残差 U-Net 的部件，不引入新的网络类型。
- 两个协议用同一套下采样步长（膝基线的那一套）。脑基线原来用的步长顺序不同，这可能让脑部结果略有变化，由与基线的对照来检验。（执行方定）
- 每个协议在统一模型里的"视图"都满足现有的模型接口，所以现有的整卷推理、输出链和模块评价可以原样使用。

### 5.2 用框训练（膝）

Proposal 规定框只能用于多示例定位，不能把框填成体素真值。这一条保留：（执行方定）

- **正约束**：医生的每个主分析框里，宿主组织上至少有一小部分体素应被判为该类异常。只要求"框里有"，不规定框里哪些体素是病变。
- **负约束**：医生的框之外，判为无该类异常。这一条是新目标带来的变化：模型模仿医生的标注，医生没标的地方模型也不标。它只用于训练，不构成"正常"的结论。
- **忽略区**：医生标了但不进主分析的框（1 级软骨病变、被排除的框、范围外类别），其范围内既不算正也不算负。

脑部沿用基线的体素级监督，不变。

### 5.3 训练

每一步各取两个协议的一个批次，梯度累加后更新一次。两个协议的步数因此相同，不因数据量不同而失衡。（执行方定）

运行登记、曝光登记、检查点、续训规则都沿用现有机制：每个协议按现有规则登记一个成员运行，统一运行把它们绑在一起。

### 5.4 输出"所见"

推理后，把预测的异常体素连成实例，每个实例生成一条所见：

- 位置：实例的外接框。
- 类别：该实例的异常类别。
- 所在结构（仅膝）：实例内被接受的预测组织中，该类别允许的组织组里体素最多的那一组；没有则写"所在结构未能确定"。
- 文字：`在{结构}上，疑似{异常}`。

**与 S7 的一处偏离**：S7 用预测实例的概率峰值点判断是否落在医生的框内。现有输出链只保存二值图，不保存概率。这里改用实例的质心体素作定位点。（执行方定；若研究者要求用峰值点，需要扩展输出链。）

### 5.5 评价

- 脑：现有模块评价，与基线逐项相同。
- 膝组织：每类 Dice，与基线相同的算法。
- 膝病变：框命中率、归属正确率（固定分母）、IoBB 在 0.1 / 0.25 / 0.5 的达标比例、组织级阳性召回；另列"医生框外的预测数"，只作描述。
- 全部在 `development_val` 上、患者等权。`locked_test` 目前为空，不读。

### 5.6 关卡

统一训练经现有的 G-BASE-A 与 G-BASE-U 放行，每个协议各自评估：膝关节的联合 scope 需要自己的 G-DATA 证据、数据使用签署、冒烟和资源批准。G-JOINT 不动，它仍然只为体素级的核心归属主张服务，保持阻断。（执行方定）

## 6. 约束

- 只用已批准的 SKM-TEA 和 ISLES-2022；GPU 不超过 2 张；服务器写入、启动作业、推送都需研究者同意。
- 私有路径、病例 ID、文件名不进仓库；私有产物目录 700、文件 600、不覆盖。
- 批准文件由研究者本人签署。
- 所有新增的数值（损失权重、top-k 比例、步数、冒烟步数）都是工程提案，写在计划文件里，真实运行前由研究者批准；不依据测试结果调整。
- 科学结论保持 `NOT_EVALUATED`，`core_target_validated` 保持 `null`。

## 7. 已知风险

1. 膝关节主分析框少：训练 106 个，开发 53 个；髌软骨、胫骨软骨在开发集各只有 5 例阳性扫描。检出指标的波动会很大。
2. 框外负约束会把医生漏标的病变当成负例训练，可能压低检出率。
3. 没有独立测试集：曝光未核实，`locked_test` 为空，结果只是开发集描述。
4. 两个协议共用一套步长，脑部可能略降。
5. 定位点用质心而不是峰值点，对形状不规则的实例可能与 S7 的原意有出入。

## 8. 分成三个计划

1. **本地实现**（`docs/superpowers/plans/2026-11-10-unified-lesion-finding.md`）：模型、框监督、训练、所见、评价、驱动，全部用合成数据在 CPU 上验证。
2. **amax 真实运行**：冻结联合划分、G-DATA、签署、冒烟、训练、开发集报告。计划一完成后再写，因为命令取决于计划一的驱动。
3. **DICOM 入口**：等有真实 DICOM 样本后另立。服务器上的两套数据看起来都不是 DICOM 原始文件，这一点尚未完全确认。
